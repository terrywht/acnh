## P1 | L1 — WPS/Office 本地文件被客户端独占锁定，openpyxl 无法写入

### 问题
- 需要向用户**正在用 WPS 桌面客户端打开**的 xlsx 写入内容（本项目：《动森鱼虫合集.xlsx》），脚本 `wb.save()` 直接失败。
- 报错：`PermissionError: [Errno 13] Permission denied` / `Device or resource busy`。

### 根因
- WPS 桌面客户端对打开中的文件持有**独占文件锁**，第三方进程无法获得写句柄。
- WPS 会在同目录生成 `~$<文件名>.xlsx` 锁文件作为「正在打开」的标记。

### 解决步骤
1. 先判断能否写入：直接尝试 `cp` 到临时文件，**看返回值**，不要用真覆盖探测（会破坏文件）。
2. 判断锁状态：`ls` 同目录看有无 `~$<文件名>.xlsx`。
   - 出现 = 正在打开；消失 = 已释放。
3. 用 openpyxl 写一个**临时新文件**（如 `待替换_<原名>_<说明>.xlsx`），不碰原文件。
4. 请用户关闭 WPS。
5. 用 `cp 临时文件 原文件` 覆盖；返回 0 即成功（本项目返回 `REPLACED_OK`）。
6. 覆盖后立即用 openpyxl 复读校验（sheet 名单、行列数、表头、抽样值）。

### 关键信息
- 锁文件命名：`~$<文件名>.xlsx`
- 覆盖命令：`cp "待替换_x.xlsx" "x.xlsx"`
- 校验片段：
  ```python
  wb = openpyxl.load_workbook(p)
  print(wb.sheetnames, ws.max_row, ws.max_column, ws.auto_filter.ref)
  ```
- **editor_sdk 通道（tencent-local-office-edit skill）只对 WorkBuddy 内置预览面板打开的文件有效** —— 用户用 WPS 客户端打开的窗口不在该 pool 里，`get_pool_status` 返回空，无法借此绕过锁。
- 环境：`C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（已装 openpyxl）

### 结果
- ✅ 已成功写入并替换（2026-10-07，《动森鱼虫合集.xlsx》「鱼结论记录」页签新增 H/I/J 三列）

### 经验
- **探测锁是否释放时，绝不能用真覆盖** —— 曾因此误覆盖一次，虽随后用正式版本重写修正，但属于可避免的风险。正确做法是判断 `cp` 返回值或先拷到 /tmp。
- 写外部数据（如 JSON 映射）进 Excel 时，若目标列型依赖公式或需跨表动态定位，**静态值 + 可复跑脚本**往往比活公式更稳妥；代价是数据源变更后要重跑。
- 交付前**必须复读目标文件校验**，不要凭脚本执行成功就宣告完成。

## P1 | L1 — GitHub push 在本机不通：沙箱代理 502、直连超时，必须走本地 7890

### 问题
- `git push origin main` 报 `schannel: server closed abruptly` / `CONNECT tunnel failed, response 502`；去掉代理变量直连报 `Failed to connect to github.com:443`（21 秒超时）。

### 根因
- 沙箱默认注入 `http_proxy/https_proxy=http://127.0.0.1:<随机端口>`（每次会话端口不同，如 49956），该代理不放行 `github.com:443` 的 CONNECT。
- 关闭沙箱后直连也不通——本机出网只走本地 Clash：`127.0.0.1:7890`（LISTENING 可查）。

### 解决步骤
1. `netstat -an | grep LISTEN` 找本地代理端口（本机为 7890）。
2. `curl -x http://127.0.0.1:7890 -o /dev/null -w "%{http_code}" https://github.com`，返回 200 即可用。
3. 推送时必须**关沙箱**（loopback 代理在沙箱外才稳定）并显式给代理：
   ```bash
   env http_proxy=http://127.0.0.1:7890 https_proxy=http://127.0.0.1:7890 git push origin main
   ```
4. 成功标志：`4a932ed..7d6a9e1  main -> main`；随后 `git log --oneline origin/main` 复核。

### 关键信息
- `mirror` = `https://ghproxy.net/https://github.com/terrywht/acnh.git` **只读**，push 报 `No anonymous write access`，只能当 fetch 兜底。
- 推送时会刷 `git-credential-manager.exe: No such file or directory` 的 store/erase 警告，**属噪音**，不影响结果（凭据由别处提供）。
- 2026-10-25 实测：走 7890 一次成功。

### 经验
- 别再逐个试「去掉代理」「换镜像」，先 `netstat` 找本地代理端口，一步到位。
- 推送后必须 `git log origin/main` 复核，不能只看 push 输出有没有报错。
