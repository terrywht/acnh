## 二、文章主线是怎么定的

主线就是刷鱼公式本身，不另立法。前面两个方案被否，各留下一条判断标准。

| 提案 | 否决理由 | 留下的判断 |
| --- | --- | --- |
| 三维解耦（排期 / 稀有度 / 经济 + 明牌影子） | 太难懂，读者进不去 | 框架必须一句话说清 |
| 100 份配额当核心 | 100 是数值约束，不是数值核心 | 约束降级为「权重」节里的一个性质 |
| **六因子公式（定稿）** | — | 六个因子 ↔ 六种玩家体感 |

六因子顺序最终是 月份 → 当日时间 → 地点 → 影子 → 权重 → 岛屿限制，先时间后空间。地点从第一位挪到第三位的原因写在 1.1 引言里：月份和时段管「什么时候有」，钓点管「在哪儿有」。

## 四、沉淀下来的方法

1. **正文只写能从配置直接数出来的数**。第三方 `fish.json` 的时间窗映射不进正文，只在内部核对用。这条是用户明确要求的，起因是拿外部数据推了一遍时间边界，结论站不住。
2. **三档时间按用户口径 8/8/8**（白天 9:00–16:59、晨昏 5:00–8:59 + 17:00–20:59、夜晚 21:00–4:59）。配置里根本没有小时字段，只有 `Prob{月}Daytime/MorningAndEvening/Night` 三档，所以小时怎么划不影响任何统计。
3. **改完文字要跑三件套校验**：正文数字多重集比对（防漏改数字）、表格逐格比对（防列错位）、图注文件名存在性（防死链）。
4. **术语替换必须连带图内文字**。`份数 → 权重` 改了 139 处正文，图 7、图 10、图 15 里的字也得重画，否则图和正文两套词。
5. **不立靶子**。删掉「社区流传的排序是 X，这个序列三处站不住」这类句式，只写数据 → 分析 → 结论。这条被用户要求过两次。
6. **封面数字要和正文同口径**。封面柱状图数的是「某月某时段有几条鱼」（32–58 种），正文 2.1 表里是「整月河海合计」（31–63）。两个口径都在，封面只写「每格 32 到 58 种」，不带月份，避免读者拿正文来质疑。
